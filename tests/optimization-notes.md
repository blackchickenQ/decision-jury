## 一、现有设计的优点（先承认，避免瞎改）

1. **防编造做得比同类项目扎实**：证词没覆盖就拒答、推理必须标注、证据引用必须逐字，这三条在提示词和代码校验里都有（debate 83–106 行 + 144–177 行）。
2. **有双层兜底**：模型输出不合法或不可用时，降级到结构化模板，不会崩，也不会冒充真实证词。
3. **不可逆动作拦截**：裁决阶段专门拦截"辞职/休学/全职投入/投入全部积蓄"（verdict 229 行）——这是产品价值观的体现，别删。
4. **大样本自动收敛**：模型和提示词两层都把"1000 人"收敛到 5-10/20，符合"低成本验证"定位。

## 二、可优化点（按优先级排序）

### P0 · 待测试验证：`coverage="none"` 的正则可能误杀

- **位置**：`app/api/debate/route.ts` 第 149–151 行
- **现状**：用正则 `/证词(未覆盖|中?没有|里?没有|不涉及)|没有相关经历|找不到能回答|未覆盖这个问题/` 扫回答前 40 字，命中就判 none 并整段替换。
- **风险**：证人如果在回答开头写"证词里没有直接说，但根据……"这种**合法的部分推理**，会被正则误判成 none，导致本来有价值的回答被扔掉。这跟"部分覆盖 partial"的语义冲突。
- **建议**：让模型输出的结构化字段 `coverage` 作为唯一判据，正则只作为模型字段缺失时的兜底；或把正则收紧到必须完全匹配整句。
- **验证用例**：TC-A2、TC-D4。

### P0 · 待测试验证：evidenceQuote 从未被真正校验

- **位置**：`app/api/debate/route.ts` 第 146–155 行
- **现状**：提示词要求"逐字引用"，代码检查了 reply 里"证词能确认"段非空，但**从未把 `evidenceQuote` 和证词原文做字符串比对**。模型可能编一句看起来像原文的话塞进去。
- **风险**：这是防编造的最大漏洞——提示词约束了，代码没兜底。评委如果现场问"这句真的在原文里吗"，会当场翻车。
- **建议**：在返回前加一道校验——`evidenceQuote` 必须是 `witness.content` 的连续子串，否则按 none 处理。
- **验证用例**：TC-D1、TC-D2、常规用例全部。

### P1 · 待测试验证：证人角色缺乏"人味"和差异化

- **位置**：`app/api/debate/route.ts` 第 83–106 行 systemPrompt
- **现状**：三位证人用同一套提示词，只靠 `witness.content` 不同来区分角色（经历核对/风险核对/行动核对）。语气统一是"温和、直接"。
- **风险**：三个证人说话像一个人在演，路演时"对质"的戏剧性出不来，容易被评委说"这不就是三份总结"。
- **建议**：给三种角色加不同的追问风格——经历核对偏"举证"、风险核对偏"泼冷水"、行动核对偏"逼你做实验"，用不同的句式开头。但**不能加编造的口癖或人设细节**（会违反防编造）。
- **验证用例**：TC-A1~A3 横向对比三位证人的语气。

### P1 · 待测试验证：裁决的"少数意见"可能流于形式

- **位置**：`app/api/verdict/route.ts` 第 173 行 `dissent` 字段
- **现状**：提示词要求"说明本裁决最可能在哪种情况下失效"，但代码对 `dissent` 没有任何非空或质量校验（对比 action 有 `validAction`、steps 有 `validSteps`）。
- **风险**：模型可能写一句正确的废话，比如"如果情况有变化，本裁决可能不适用"——等于没有。
- **建议**：加一条校验——`dissent` 必须含具体条件（可观察的名词/数字），否则用模板里的 `dissent` 兜底。
- **验证用例**：TC-F3。

### P1 · 待测试验证：glm-4-flash 在长证词下可能丢细节

- **位置**：`app/api/debate/route.ts` 第 127 行 `model: "glm-4-flash"`，`max_tokens: 650`
- **现状**：search 接口把证词截断到 5000 字（第 63 行），但 debate 的 `max_tokens=650`，长证词下模型可能只抓住开头部分。
- **风险**：证人回答"以偏概全"，引用的总是证词第一段。
- **建议**：测试时专门找一条长证词（>2000 字），看是否总引用开头；若是，考虑把证词提到 userPrompt 前部并标注关键段落，或换更大的模型/提高 max_tokens。
- **验证用例**：TC-A1（选长证词样本）。

### P2 · 检索结果的质量未纳入提示词

- **位置**：`app/api/search/route.ts` 第 55–77 行 `formatWitnesses`
- **现状**：只按 `ContentText` 长度取前 5000 字，标题和作者信息分离。搜索结果里"劝退帖""成功经验帖"混在一起，都当证人。
- **建议**：在证词卡里增加"立场"字段（支持/反对/中性），让对质时能形成交锋——这也是产品观点"观点交锋"的落点。但这个改动涉及数据结构，属于下一版，48 小时内可不做。
