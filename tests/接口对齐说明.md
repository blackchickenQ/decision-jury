## 真实接口签名（取自 app/api/*/route.ts）

### 1. `/api/search` 传唤证人

**请求**
```json
{
  "caseFile": {
    "decision": "我要不要休学去做出海创业项目",
    "reason": "觉得出海 AI 工具上限最高",
    "constraint": "最多休学一年，不能烧完积蓄"
  },
  "query": "休学 出海创业 失败 教训"
}
```
> `caseFile` 和 `query` 都可传；只有 `query` 时会包装成 `caseFile.decision`

**返回**
```json
{
  "witnesses": [
    {
      "name": "证人 A",
      "tag": "奇绩创坛",
      "role": "经历核对",
      "quote": "证词摘要（≤180字）",
      "content": "完整证词原文（≤5000字）",
      "sourceUrl": "https://www.zhihu.com/.../answer/...",
      "title": "原回答标题",
      "isDemo": false
    }
  ],
  "warning": ""
}
```
- 证人固定 3 位，`role` 取值：`经历核对` / `风险核对` / `行动核对`
- `isDemo=false` 表示真实知乎回答且带 `sourceUrl`；检索失败时返回 `isDemo=true` 的演示证人 + `warning` 说明
- 搜不到时不是空数组，而是 3 位明确标注的演示证人（防编造设计）

### 2. `/api/debate` 当面对质

**请求**
```json
{
  "witness": { "name": "证人 A", "role": "经历核对", "quote": "...", "content": "..." },
  "userMessage": "你在接触学生创业者时，怎么判断真实需求？",
  "caseFile": { "decision": "...", "reason": "...", "constraint": "..." },
  "strategy": "证据追问",
  "history": [ { "role": "user", "who": "", "text": "..." } ]
}
```
> `strategy` 取值：`证据追问` / `风险追问` / `行动追问`

**返回**
```json
{
  "reply": "【证词能确认】…【对你的启发】…",
  "takeaway": "刘看山记入案卷的一句话",
  "coverage": "partial",
  "warning": ""
}
```
- `coverage` 取值：`direct` / `partial` / `none`
- `none` 表示证词未覆盖，此时 reply 只有一句缺失说明、不给建议（防编造）

### 3. `/api/verdict` 出具裁决

**请求**
```json
{
  "caseFile": {
    "mode": "single",
    "decision": "...",
    "reason": "...",
    "constraint": "...",
    "options": ["A", "B"]
  },
  "insights": [ { "text": "看山笔记一条" } ],
  "witnesses": [ /* search 返回的证人数组 */ ],
  "messages": [ { "role": "user", "who": "证人A", "text": "..." } ]
}
```
> `mode` 取值：`single`（单决定） / `compare`（二选一） / `premortem`（事前验尸）

**返回**
```json
{
  "verdict": "有条件通过，先验证再投入",
  "summary": "哪些证据支持、哪些仍缺失",
  "deathCause": "最可能导致失败的根因",
  "action": "7 天内可完成的一个最小验证动作",
  "successMetric": "可观察的通过阈值",
  "stopCondition": "明确的停止或转向条件",
  "reviewDate": "14 天后复盘",
  "conditions": ["条件1", "条件2", "条件3"],
  "experimentSteps": [
    { "title": "步骤名", "detail": "具体怎么做", "metric": "留下什么证据" }
  ],
  "dissent": "少数意见：本裁决最可能失效的情况"
}
```

## 两份文档字段对照

| 用途 | 2 号文档字段 | 现有代码字段 | 处理建议 |
|---|---|---|---|
| 证人标识 | `id` (w1/w2/w3) | 无 id，用数组下标 + `name` | 前端按 index 取即可，无需 id |
| 证人视角 | `perspective` 失败者/成功者/旁观者 | `role` 经历核对/风险核对/行动核对 | **建议保留 2 号想法**：在 search 返回里**新增** `perspective` 字段，不动 `role` |
| 证词结构 | `testimony`{time,action,result,lesson,boundary} | `quote` + `content` 两个文本字段 | 可在 debate prompt 里让模型按五要素抽取，作为**新增** `testimony` 字段返回 |
| 原文链接 | `source.url` | `sourceUrl` | 前端改取 `sourceUrl`，或后端同时返回 `source`（新增） |
| 未找到 | `found: false` | 3 位 `isDemo=true` 证人 + `warning` | 代码的处理更安全（不会空屏），建议前端按 `isDemo` 判断 |
| 对质输入 | `witnessId` + `question` + `round` | `witness` 对象 + `userMessage` + `strategy` | 前端传完整 witness 对象；`round` 可从 `history.length` 推出 |
| 对质输出 | `inBoundary` | 无 | **建议新增** `inBoundary` 布尔字段到 debate 返回 |
| 裁决结论 | `verdict: reject/conditional` | `verdict` 是中文短句 | 可**新增** `verdictType: "reject"/"conditional"` 供前端渲染徽章 |
| 裁决依据 | `basis[{witnessId,quote,url}]` | 无独立 basis，证词在 witnesses 里 | 可新增 `basis` 数组；现有 `dissent` 已是少数意见 |
| 最小动作 | `minAction` | `action` | 同一含义，前端取 `action` 即可 |
| 免责声明 | `disclaimer` | 无 | **建议新增**，产品与合规都需要，成本极低 |
